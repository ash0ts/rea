# Standalone file-format recovery: frozen controlled study

Question: does a guided REA workflow improve functional recovery of an unfamiliar file reader over the same coding agent with ordinary inspection and execution tools? A separate sample-only arm asks how much the shipped application contributes. Neither arm is claimed to represent human experts or a universal reverse-engineering baseline.

Four original offline laboratory applications: compressed chunk directory, transactional event journal, dictionary/column encoding, and a hierarchical record archive. Each has a distinct payload interpretation, supported versions, and multi-module reader. They share a container header and utility module. They are intentionally small controlled artifacts, not real commercial apps, malware, native binaries, or evidence of large-scale reverse-engineering ability. Minification uses pinned Terser 5.44.1 without artificial obfuscation or renamed property APIs. Prior model memorization of these newly authored implementations is implausible, but knowledge of common encodings remains useful and legitimate.

Source and expected results are outside the agent filesystem. Only minified application modules, manifest, two binary examples and matching JSON outputs are supplied. The sample-only arm gets the same examples and tools without the application. The required artifact is one Python-standard-library decoder accepting an arbitrary input path. The independent evaluator copies only that decoder to a fresh, offline Python-only container with no application, Node runtime, previous outputs or reference code. Explanations and tool use do not earn functional points.

Python encoders construct records and intended outcomes. Separately implemented JavaScript readers must reproduce those outcomes for every visible/hidden case and reject each malformed case before freezing. This cross-language check reduces shared implementation assumptions; it is not an independent human review. Twelve hidden inputs per target vary size, versions, flags, values, Unicode and ordering; seven malformed-input controls cover magic, truncation, checksum, version, trailing bytes, flags and semantically truncated payload with a valid checksum. Visible examples must decode before invalid-input rejection receives credit. Empty results, dormant state, transaction rollback and inherited inactive flags are deliberate negative controls.

Three repetitions of each of four targets in each of three arms produce 36 scored attempts. Three separate attempts on a distinct qualification format validate infrastructure. All attempts are preserved. The primary contrast is baseline (application plus ordinary tools) versus REA (same plus REA). The data-only arm is diagnostic, not the headline baseline. The shared prompt contains conditional REA workflow guidance; this measures that guided workflow, not pure tool availability or the effect of forcing a particular analysis result. Each treatment should analyze once and investigate one specific relationship using retained Evidence, with actual compliance reported separately. Successful tool invocation is not proof that the result caused the submitted implementation.

Latin-square arm ordering rotates within target/repetition. Attempts run sequentially with fresh containers and MCP sessions. There is no shared conversation state. Host/image caches and unrelated host work are not controlled; timing is descriptive. These are four task families, not 36 independent targets. Three trials describe observed stability, not a general superiority finding.

Model: moonshotai/Kimi-K2.7-Code via Forge, temperature 0.2, maximum 16,384 output tokens per request, 24 requests, 600 agent seconds, and $5 per attempt. No model retries or substitutions. Unknown paid calls retain their reservation. The campaign reservation ceiling is $200, within the user's subsequently authorized unlimited total budget; per-attempt limits provide comparable stopping conditions. Pricing verified November 9, 2026: $0.60/M input and $3/M output. Reservations use the shared runner's conservative $0.71/$3.50 rates. Estimates are not settled billing.

Primary outcome: all twelve unseen valid inputs match expected JSON exactly, including ordering, integer and Boolean types. Secondary outcomes: individual hidden-input pass fraction, all seven rejection controls with valid-input controls, and complete task pass including visible cases. Missing decoder, incorrect semantics, invalid-input failures, budget stops, timeouts, infrastructure failures, and unavailable checker judgments remain distinct. Aggregate per attempt, then report paired outcomes per target/repetition; never pool individual records as independent trials. Also report task tokens including schemas/repeated context, request count, elapsed agent time, estimated cost, local container CPU and peak memory. Remote inference resources are unavailable; controller peak memory is lifetime-scoped. Explanations receive a separate descriptive evidence audit, never undisclosed model-judge points.

Freeze input/oracle hashes, image IDs, code, prompts, model settings, MCP schemas, order and this contract before qualification and scoring. A qualification task failure does not disqualify a difficult target; qualification requires completed checking, live tool calling, telemetry readback, Evidence export where applicable, and cleanup. Infrastructure failures stop qualification and are retained under a new campaign identity if repairs affect frozen code. Scored failures are never replaced or rerun. The checker is not changed after scored outcomes are observed.

Safety boundary: original offline fixture code only; no network, credentials, Docker socket, home directory or reference source in agent containers. All generated code remains isolated. Controller credentials remain in the controller. REA's public API/runtime is unchanged. Source, prompts, submissions, judgments, traces, resource observations and complete canonical Evidence are retained locally and exported to the existing private wandb/rea-showcase project. No public publication or upstream integration is implied.

Stop on input/schema drift, unresolved cleanup or unsafe execution scope. Publication failure leaves local results and is repaired independently of inference. Preserve owned resource receipts through cancellation and final cleanup. A successful study may show no REA gain, extra cost, or reduced success. The decision is whether retained structure and provenance justify their measured cost for these tasks, and what broader testing remains necessary.
